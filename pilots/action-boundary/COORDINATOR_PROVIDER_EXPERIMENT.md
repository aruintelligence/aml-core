# Coordinator-to-provider uncertainty experiment

Run `node --test test/action-boundary-coordinator-provider-recovery.test.js` with Python 3. The test uses the existing stronger file authority with its epoch-aware claim hook, a separate SQLite claim subprocess, and a separate SQLite provider subprocess. The only provider effect is a row in a temporary database. The host constructs exact request bytes from the frozen prepared request and a stable host operation ID.

In both cases the provider child exits without an acknowledgment and the host reports `outcome_unknown`. A new authority instance cannot consume the grant again and never calls its second callback. After a simulated post-commit acknowledgment loss, a read-only provider query returns a matching operation and effect ID. After a simulated pre-commit interruption, it returns no row. Absence is meaningful only within this fixture's complete database-view assumption; it is not general proof that an external action never occurred. No host retry is attempted.

This first pair is project-authored E2 evidence for a **local composition**. In these two cases the host process does not crash or persist a unified AVEP event journal; the new authority instance is not a restarted host process. The provider DB and coordinator DB share the same OS identity and machine. The provider response is unsigned, and there is no independent verifier, independently administered observer, authenticated human approval or physical external effect. The existing `local-host-restart-worker.mjs` separately exercises a host-process restart with unauthenticated file markers. Do not combine those two separate results into a stronger claim.

## Actual host-process crash inside dispatch

Run `node --test test/action-boundary-coordinator-provider-crash.test.js`. A dedicated host worker syncs a test intent, consumes the externally anchored claim, sends the exact frozen request to the provider subprocess, and exits **inside** the protected callback after the provider exits without acknowledgment. A fresh host process reads the retained intent, attempts replay, and queries the provider database read-only.

The authority deliberately strands its local lock on an abrupt host exit. Recovery reports `indeterminate/authority_busy_or_crashed` on replay, with zero callback entries. The coordinator retains one spent claim. A matching provider row is visible only in the post-commit case; the pre-commit case has no row. Both have unknown host outcomes, no automatic retry, and no independent confirmation. An operator must reconcile the stranded lock; this fixture does not implement a safe automatic lock recovery protocol. A missing row is evidence only under this fixture's complete-view assumption and does not generally establish absence of an external effect.

The first focused run failed 0/2 because the test intent serialized the prepared request in insertion order while dispatch passed canonical frozen bytes. The fixture now serializes with the published canonical JSON routine before persisting the intent; the corrected focused run passed 2/2. The host journal, provider database, and coordinator database remain same-identity local storage, not independently authenticated evidence. Correlated rollback or a compromised host can defeat this experiment's assumptions.
