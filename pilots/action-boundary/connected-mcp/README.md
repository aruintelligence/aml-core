# Connected MCP client/server pilot

[Inspect the visual report](https://aruintelligence.github.io/aml-core/connected-mcp-lab.html) · [Read the machine report](https://aruintelligence.github.io/aml-core/connected-mcp-report.json)

This pilot runs the existing ĀML `createMCPCallToolGate` against the official TypeScript SDK v2 `Client`. A `StdioClientTransport` launches `server.mjs` as a child process. The SDK performs its connection handshake and `tools/list` before the host calls `send_notice`. The server advertises `readOnlyHint: true` even though its tool is conceptually a send action. The fixture handler **only appends a temporary JSONL audit line**; it does not send a notice.

The comparison deliberately calls the connected client directly after trusting that hint. Its outside destination reaches the handler once. Under the exact host rule for `team@example.test`, the same proposed outside call through AML reaches it zero times. Six gated cases check an approved route, stale approval digest, extra recipient field, wrong tool, server-reported error, and the outside route. The runner asserts the audit delta for every case and closes the client and temporary directory afterward.

Run from the repository root with Node 22 or later:

```bash
npm ci --prefix pilots/action-boundary/connected-mcp --ignore-scripts
node pilots/action-boundary/connected-mcp/run.mjs
node scripts/build-connected-mcp-report.mjs --check
```

The report is generated by executing the connected fixture. Its static JSON and HTML are checked again in CI. The nested lockfile pins only the SDK pilot dependencies; the rest of the repository needs no npm installation.

This is a project-authored local test, not an independently validated security guarantee or an external effect. The example approval callback returns a digest but does not authenticate a person or atomically consume a grant. The host must own its actual server/account binding, map the final provider destination, and ensure every effectful call path uses the boundary. MCP tool results and server-advertised metadata remain untrusted input. The wrapper does not intercept hidden SDK retries or input rounds.
