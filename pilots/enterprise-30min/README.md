# ĀML™ Enterprise Pilot — 30 Minutes

This pilot demonstrates how an existing AI product can add an ĀML accountability boundary **without rewriting its UI stack**.

## What the pilot proves

The pilot can demonstrate software properties that are directly testable:

- machine intent can be converted into ĀML;
- an AI Interface Firewall™ policy can allow or suppress proposed UI;
- runtime context can alter policy outcomes;
- execution receipts can be generated and verified;
- View Meaning™ can summarize the decision trail;
- semantic/policy diffs can be added to CI.

It does **not** prove that present attention/restoration values objectively measure people, that a declared AI intent is truthful, or that the application is WCAG/security/regulatory compliant.

## Files

- `intent-allowed.json` — a low-cost explanatory interface proposal
- `intent-sensitive.json` — a proposal that requests personal-data collection and consent
- `context-allowed.json` — runtime context with required consent
- `context-denied.json` — runtime context without consent
- `run.mjs` — executes the pilot through the real AML core API

## Run

From the repository root:

```bash
node pilots/enterprise-30min/run.mjs
```

The script runs three scenarios:

1. calm explanatory UI → expected to render;
2. sensitive UI without consent → expected to be withheld by the human-first profile;
3. sensitive UI with consent → policy evaluation is rerun under the supplied context.

It then verifies every receipt generated by the pipeline.

## Integration pattern

```text
AI / agent
   ↓ machine intent
AML Interface Firewall
   ↓ allow / suppress + receipt
existing React / Next / browser UI
```

The existing renderer remains in place.

## Pilot success criteria

A team should be able to answer:

- What did the AI propose?
- What meaning was declared?
- Which policy profile ran?
- Which runtime context was considered?
- What rendered or was withheld?
- Can the decision receipt be verified?
- Can a reviewer inspect the decision with View Meaning?

## Production boundary

Production adoption still requires normal application security, output escaping/sanitization, authentication/authorization, privacy review, accessibility testing, observability, key management, and threat modeling. AML is an accountability/policy layer; it is not a substitute for those controls.
