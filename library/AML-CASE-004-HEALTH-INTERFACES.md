# AML-CASE-004 — Health Interfaces

**Status: DRAFT casebook built on SHIPPED AML primitives**

Health-related interfaces can combine urgency, sensitive data, reminders, AI-generated guidance, and accessibility needs. That makes them a useful domain for testing whether interface intent and policy evidence should be explicit.

## Candidate AML uses

- require declared purpose for generated health prompts
- attach consent/privacy context to personal-data requests
- preserve receipts for why a sensitive prompt appeared
- apply reduced-motion and text-alternative checks
- distinguish essential alerts from promotional interruption
- review semantic changes through Meaning Gate

A health interface should not rely on ĀML as a medical decision system. ĀML does not determine diagnosis, treatment, clinical truth, or legal compliance.

The narrower research question is whether an interface firewall can help teams make the **presentation decision** inspectable: why did this element appear, what policy context governed it, and can the decision be reproduced later?

This casebook is a product/research scenario, not evidence of healthcare adoption.
