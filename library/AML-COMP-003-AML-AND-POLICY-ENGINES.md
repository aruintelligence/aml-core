# AML-COMP-003 — ĀML and General Policy Engines

**Status: SHIPPED comparison paper**

A general policy engine can evaluate rules over arbitrary application data. ĀML is narrower: it is shaped around the human-interface boundary.

That means the technologies can complement each other.

A general policy engine may answer:

- Is this user authorized?
- Is this resource accessible?
- Does this transaction satisfy organization policy?

ĀML asks interface-specific questions such as:

- What purpose is this generated element declaring?
- What attention cost and restoration value are being evaluated?
- Should this element render under the selected interface policy?
- What receipt should preserve the decision?
- Did the meaning change between two versions?

ĀML should not be marketed as universally better than mature policy engines. The differentiator is its interface-native vocabulary, receipts, View Meaning, and Meaning Gate workflow.

An enterprise architecture could use an existing authorization/policy system for business rules and AML as a final accountable interface layer before pixels.
