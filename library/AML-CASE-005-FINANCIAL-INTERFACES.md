# AML-CASE-005 — Financial Interfaces

**Status: DRAFT casebook built on SHIPPED AML primitives**

Financial interfaces can generate consequential prompts around transfers, credit, fees, offers, investments, subscriptions, and personal data.

## Candidate AML uses

- declare the purpose of generated offers
- keep payment actions separate from promotional pressure
- record why a fee or warning prompt appeared
- require consent context for optional data collection
- preserve receipts around dynamically generated financial UI
- use Meaning Gate when a semantic change alters urgency, disclosure, or data collection

ĀML is not a financial-advice engine and does not determine whether a transaction is suitable, lawful, or financially beneficial.

Its proposed role is at the interface boundary: make the presentation decision inspectable and replayable.

A useful pilot would choose one generated financial UI region, define a narrow policy, run ALLOW/SUPPRESS fixtures, and compare receipts before and after a semantic change.

This casebook is a proposed application area, not evidence of financial-industry adoption.
