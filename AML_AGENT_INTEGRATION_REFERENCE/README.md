# Local function-tool reference

Run `node AML_AGENT_INTEGRATION_REFERENCE/local-outbox.mjs`. The host defines a `local_outbox.append` tool, an exact resource policy, an approval choice and a one-use local grant. The model-proposal role is represented by input arguments supplied to the guarded function-tool adapter. The protected callback appends a record to a temporary **local** file; the harness reads that file to confirm its own side effect. It sends no email and contacts no service.

The five cases cover denied approval, changed payload, successful approval, replay and an error **after** a local append. The last case returns `unknown`, although the harness can see its own local file record. This deliberately demonstrates why a generic callback failure cannot be reported as no external effect. No actual human UI or model is included; the host approval decision is scripted for repeatability.

All receipts are generated by the project code and are not signed. The grant store is a one-machine pilot with the limitations in `pilots/action-boundary/README.md`. Integrating a real provider requires authenticated human approval, exact target resolution, stable operation ID, idempotency/reconciliation and a transactional external authority. See `AML_EXECUTION_INTEGRITY_SPEC.md`.
