# AVEP research gate: prior art and public disclosure

Status: preliminary engineering review, November 2026; no novelty, patentability, trademark or ownership opinion. Source tree pinned in `AML_ARCHITECTURE_CLAIMS_MAP.md`. This document records established mechanisms before any new AVEP/1 wire identifier or implementation is published. Existing ĀML source, draft PRs, specifications and MIT-licensed material are public; draft status does not confer confidentiality. No private legal or commercial correspondence belongs in this repository.

| Existing technology / primary source | Existing mechanism and guarantee under its assumptions | ĀML current mechanism | Proposed additional experiment, **not** a novelty claim | Falsifying comparison |
| --- | --- | --- | --- | --- |
| [Zanzibar (USENIX 2019)](https://www.usenix.org/conference/atc19/presentation/pang) | Consistent global authorization for permissions over a backed storage system | Host exact policy and local/optional epoch authority | Compare exact action binding and authority epoch against a consistent authorization service | If the same policy/action/effect evidence can be reconstructed from the established service under identical trust assumptions, no distinct guarantee follows. |
| [Open Policy Agent](https://www.openpolicyagent.org/docs/) and [decision logs](https://www.openpolicyagent.org/docs/management-decision-logs) | Policy as code and logged decisions; caller must enforce decisions | ĀML host policy and dispatch gate | Correlate frozen proposal and exact provider request with the decision | A host that bypasses either gate defeats both; compare observable request binding, not marketing labels. |
| [Macaroons paper](https://research.google/pubs/macaroons-cookies-with-contextual-caveats-for-decentralized-authorization-in-the-cloud/) | Attenuated, context-aware authorization credentials | Proposal digest, actor/scope/grant in pilots | Test portable scope/binding evidence | A correctly caveated token plus conventional enforcement may provide the same authority property. |
| [Transactional outbox pattern](https://microservices.io/patterns/data/transactional-outbox.html) | Persist intended outbound work with application state in one transaction; delivery can still duplicate | Local journal and operation ledger | Atomically record authority consumption and dispatch intent in a controlled store | If an outbox with request identity and idempotent consumer matches the same failure model, no new execution guarantee is established. |
| [Temporal retry semantics](https://docs.temporal.io/encyclopedia/retry-policies) | Durable workflow/activity retries with explicit idempotency burden for effects | In-memory state reducer and local crash fixture | Compare lost acknowledgment and reconciliation behavior | If Temporal plus provider idempotency and evidence query produces the same observer-verifiable result, AVEP adds no execution guarantee. |
| [SQLite transactions](https://sqlite.org/lang_transaction.html) and [isolation](https://sqlite.org/isolation.html) | Atomic, serializable writes on one database when its filesystem and durability assumptions hold | Local file claims and opt-in file checkpoint/claim hooks | Put grant, epoch and operation identity under one transaction in a separate test service | A restored coordinator database or bypassed service breaks anti-rollback; one SQLite host is not distributed consensus. |
| [Certificate Transparency RFC 9162](https://www.rfc-editor.org/rfc/rfc9162.html) | Signed, auditable append-only Merkle log with consistency proofs under witness assumptions | ĀML release/governance evidence and file authority checkpoint | Test independently retained authority head and rollback rejection | Jointly restore or compromise the witness and log; a hash chain alone does not authenticate execution. |
| [MCP tool specification](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/server/tools.mdx) and [authorization](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/basic/authorization/index.mdx) | Tool invocation and transport authorization; tool annotations require trust judgment | Host-controlled MCP call gate and local connected pilot | Bind a concrete provider request/account and separate provider observation | If MCP transport/host authorization already records equivalent request and provider evidence, action labeling alone is not a contribution. |

The possible **research contribution** is a reproducible composition of exact human-approved action identity, atomic authority consumption, provider idempotency/uncertainty, and separately attributable evidence. The individual mechanisms above are established. No experiment here yet compares the combined system against a matched existing design, so measurable differentiation and independent reproduction are **unverified**.
