## A-03 decision

The smallest next experiment should reuse the stronger authority's `claimOnce`/epoch/checkpoint interfaces, not build a second file-based claim system. Compare two **distinct** controls: (A) a separately operated transactional claim/epoch service with an atomic consumption decision; (B) an independently retained monotonic checkpoint that rejects an older local authority state. A pure checkpoint detects rollback and fails closed; an atomic claim additionally mediates one-use dispatch. The existing file implementations establish API behavior under local tests, but their separate directories share an OS identity and may share a backup domain. A controlled SQLite service in another process can test transaction and restart semantics on one machine; it is not multi-machine consensus, independent administration, or proof of provider completion.

Before publishing any new AVEP wire format, perform the disclosure review and pin its compatibility/authority assumptions. No new inventive mechanism is asserted in this factual map. Existing MIT grants, attribution, stable tags and preview identifiers are unchanged.

## Controlled coordinator follow-up

`sqlite-epoch-coordinator.py` and its Node adapter reuse the existing epoch-aware hook. Seven focused tests cover local rollback with the coordinator retained, concurrent claim workers, a claim/revocation race, stale epoch, acknowledgment loss after commit, coordinator outage, and a **joint rollback counterexample**. This is an experimental standard SQLite transaction behind an existing interface. It demonstrates one-machine serializable decisions with the database intact, not independent retention, distributed coordination, authenticated approval, external provider completion or an AVEP verifier.
